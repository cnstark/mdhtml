# mdhtml 技术方案

一个 HTML 就是一个 md：单文件、自包含、可查看、可编辑、可划词批注，保存即原地改写自身。

- 文件格式：`xxx.md.html`
- 保存方式：File System Access API 原地覆写（Chrome/Edge 桌面端），不支持的浏览器降级为下载覆盖
- 工作名：mdhtml（可改）

---

## 1. 总体架构

采用 **quine（自复制）模式**，参照 FeatherWiki / TiddlyWiki：

```
xxx.md.html = 应用代码（HTML+CSS+JS，全部内联） + 数据（md 源码，末尾附带批注 JSON 注释块）
```

文件内结构：

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>{文档标题}</title>
  <style>/* 全部样式内联 */</style>
</head>
<body>
  <!-- 数据块：md 源码 -->
  <script id="md-source" type="text/markdown">
# 文档标题
正文……

<!-- mdhtml-annotations
[]
-->
  </script>
  <!-- 应用代码：渲染器 + 编辑器 + 批注 + 保存逻辑，全部内联 -->
  <script>/* app */</script>
</body>
</html>
```

**为什么保留 HTML 应用壳**：编辑功能需要完整应用代码。md 源码完整内嵌，批注随源码提取（见 §5 转换工具），「一个 html 就是一个 md」成立。

打开即渲染：JS 读取 `#md-source` → 解析 md 末尾批注注释块 → marked 渲染到视图区 → 逐条锚定高亮。

## 2. 保存：原地改写

核心流程：

1. 浏览器打开 `file:///…/xxx.md.html`，页面检测 `window.showOpenFilePicker` 是否可用。
2. 首次保存时提示用户**选取该文件本身**（一次授权），获得 `FileSystemFileHandle`；校验文件名与当前文件一致，防止选错。
3. 之后每次保存：`handle.createWritable()` → 写入**重新生成的完整 HTML** → `close()`。静默无弹窗。
4. 句柄只在本次会话内存中有效；重新打开文件需再授权一次（点一下），这是 API 的安全限制，可接受。

**关键点：保存不是序列化当前 DOM。** 当前 DOM 里有渲染产物、高亮标记、UI 状态，序列化会越存越脏。正确做法是保存 = `模板(md源码)` 重新拼装。批注增删改时立即写回 md 变量及源码编辑器：

```js
function serialize(md) {
  return TEMPLATE
    .replace('@@MD@@', () => escapeMarkdown(md));
}
// md 内（包括批注 JSON）的 </script> 按同一规则转义，防止提前闭合数据块
```

模板字符串由应用自身持有（应用代码里包含模板骨架，数据位用占位符标记），保证「重新生成的文件」与「原文件的应用部分」字节级一致。

**降级路径**：Firefox / Safari / 安卓 Chrome 无 File System Access API，保存按钮降级为「下载新 HTML，手动覆盖原文件」（TiddlyWiki 方式）。手机上只读+批注可看，写回靠桌面端。

**待实测项**（开工第一周验证）：
- `file://` 协议下 File System Access API 的可用性（文档称可用，需实测确认）；
- 能否把句柄存入 IndexedDB 实现跨会话免授权（`file://` 源下 IndexedDB 行为各浏览器不一，存不上就接受每次打开点一次授权）。

## 3. 查看与编辑

- **查看模式**：marked 渲染 + DOMPurify 消毒；GFM（表格、删除线、任务列表）；代码块用 highlight.js 语法高亮；标题锚点；**左侧大纲侧栏**（由 H1–H3 生成，点击跳转，当前位置高亮，可折叠）。全部库内联进文件，无 CDN 依赖（离线可用、单文件可拷走）。
- **图片**：两种来源都支持——①相对路径引用（`./img/a.png`）：`file://` 下浏览器可直接加载同目录图片，适合文件就地使用，但文件单独拷走时图片会丢；②CLI `build` 时可选 `--embed-images` 把本地图片转成 base64 data URI 内联进文件，真正单文件自包含（代价是体积变大）。规则：转换时默认保留原始引用并警告本地图片，`--embed-images` 才内联。
- **编辑模式**：左侧 textarea 源码 + 右侧实时预览（分屏），`Cmd/Ctrl+E` 切换；`Cmd/Ctrl+S` 保存。
- **drawio 图（浏览器内实时渲染，方案 B）**：drawio 官方嵌入 viewer（`viewer.min.js`，约 1–2MB，Apache-2.0）**内联进每个文件**，离线可渲染。md 中两种写法：
  1. ` ```drawio ` 代码块，内嵌 mxfile XML 源码（图源即在文档内，单文件自包含）；
  2. 用图片语法引用本地 `.drawio` 文件，例如 `![架构图](./arch.drawio)`：CLI `build` 时读取 mxfile XML，并把该引用展开为 ` ```drawio ` 代码块后注入模板；文件不存在则报错并中止构建。输出文件不再依赖原 `.drawio` 文件，且无论是否传 `--embed-images` 都会展开。
  `extract` 提取的是构建后的 Markdown；已展开的 drawio 代码块保留为代码块，不还原为原来的文件引用。
  运行时渲染器把 drawio 块转成 `<div class="mxgraph">` 交给 viewer 渲染；双击可开 lightbox 看大图。
  **代价与边界**：每个文件体积 +1–2MB（viewer 常驻内联，接受）；v1 不在浏览器内编辑 drawio（完整编辑器数十 MB，不可内联），改图 = 直接编辑 ` ```drawio ` 块内 XML，或用 drawio 桌面版改完贴回/重新 build。
- v1 不做 Typora 式所见即所得（block 级混排编辑复杂度高，留作 v2 候选，可评估 milkdown/Tiptap）。

## 4. 批注

**数据格式：W3C Web Annotation**，数组附在 md 源码末尾的 HTML 注释块中；每篇文档至多一个，无块时保存追加空数组。每条：

```json
{
  "id": "urn:uuid:…",
  "type": "Annotation",
  "created": "2026-10-27T…",
  "body": { "type": "TextualBody", "value": "这段不对", "format": "text/markdown" },
  "target": {
    "selector": [
      { "type": "TextQuoteSelector", "exact": "被选中的原文", "prefix": "前文32字", "suffix": "后文32字" },
      { "type": "TextPositionSelector", "start": 1024, "end": 1035 }
    ]
  }
}
```

注释块使用 `<!-- mdhtml-annotations` 起始，末尾 `-->` 结束。批注随 md 一起保存，CLI `extract` 不会丢失；marked 将 HTML 注释作为不可见节点传递，阅读视图不显示。编辑模式直接修改注释块后，在切换查看或保存时重新解析。解析失败则按空批注显示并提示一次，保留原始块内容。含旧 `#annotations` 数据块的文件迁移到新模板时，批注进入 md 末尾，保存后旧块消失；旧版自包含 HTML 可先用 CLI `extract` 迁移批注，再 `build` 更新模板。

**锚定策略**（这是批注功能的核心难点，因为文档会被编辑）：

1. 首选 TextQuoteSelector：在渲染后纯文本中精确匹配 `exact`，多处匹配时用 `prefix/suffix` 消歧；
2. 兜底 TextPositionSelector：字符偏移快速定位候选位置；
3. 都找不到 → 标记为「失锚」，在侧栏单独列出，可一键删除或重新选择文本挂载。

**交互**：查看模式下划词 → 弹出「批注」按钮 → 输入框（支持 md）→ 保存后立即高亮 `<mark>` 并写入内存批注表；侧栏批注列表，点击跳转定位；批注可编辑、删除。编辑文档 → 重新渲染 → 全部批注重新锚定。

库选择：锚定算法可参考 Hypothes.is 作者的 **anchor-quote**（容错引用匹配）；弹层 UI 自己写（量小，Recogito 全套引入偏重，且其样式侵入性强，不符合单文件克制原则）。

## 5. 转换工具（CLI）

Python（仅标准库），与 JS 侧共用同一套转义规则：

```bash
mdhtml build 笔记.md            # → 笔记.md.html（套用模板注入）
mdhtml extract 笔记.md.html     # → 还原纯 笔记.md
mdhtml check  笔记.md.html      # 校验数据块完整性
```

模板文件 `template.html` 是唯一事实来源：CLI 往空模板里注入 md；浏览器内保存时用文件内嵌的同一模板再生成。版本号写入 `<meta name="mdhtml-version">`，CLI 可对旧版文件做模板升级（读数据→套新模板→写回）。

## 6. 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| M1 | 模板 + CLI build/extract + 查看渲染 | md → html 双向无损，浏览器打开即渲染 |
| M2 | 编辑 + FS API 原地保存 | Chrome 打开 → 改 → Cmd+S → 文件原地更新，重开内容在 |
| M3 | 划词批注 + 锚定 + 失锚处理 | 批注随文件保存，编辑文档后批注自动重锚 |
| M4 | 打磨：目录、搜索、批注侧栏、暗色主题 | 日常使用顺滑 |

## 7. 明确不做

- 多人协作 / 服务端同步（单人本地工具）
- 所见即所得编辑（v1 用源码+预览）
- 手机端写回（API 不支持，手机只读）
- 云端存储、账号体系
